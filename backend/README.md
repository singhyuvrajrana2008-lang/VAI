# RidgeWatch backend foundation

Python/FastAPI backend scaffold for the RidgeWatch prototype. This is decision-support research software, not an operational warning service. Experimental status must not be used for evacuation decisions or as a replacement for official guidance.

## Local setup

From the repository root:

```bash
cd backend
python -m venv .venv
source .venv/bin/activate  # Windows: .venv\\Scripts\\activate
python -m pip install -r requirements.txt
uvicorn app.main:app --reload
```

The API is at `http://127.0.0.1:8000`; interactive OpenAPI documentation is at `/docs` and the schema at `/openapi.json`. Run tests from `backend/` with `pytest -q`.

To enable the synthetic example catchment for UI development, set `RIDGEWATCH_MODE=demo` before starting the server. It is named `Example catchment (DEMO)`, has no fabricated polygon or observations, and all responses tied to it carry `is_demo=true`. With the default `RIDGEWATCH_MODE=live`, the catchment list is empty because no verified live source/catchment is configured. No live provider is enabled.

## Environment

- `RIDGEWATCH_ENVIRONMENT` (default `development`)
- `RIDGEWATCH_MODE` (`demo` or `live`; default `live`)
- `RIDGEWATCH_PROVIDER_TIMEOUT_SECONDS` (default `5.0`; used by provider adapters)
- `SUPABASE_URL` and `SUPABASE_SERVICE_ROLE_KEY` (or the `RIDGEWATCH_SUPABASE_URL` and `RIDGEWATCH_SUPABASE_SERVICE_ROLE_KEY` aliases; optional indicators only; database client/persistence is not yet implemented)

Do not expose a Supabase service-role key to a browser. Supabase credentials currently do not enable persistence; health reports this as `configured_but_not_connected` if both are present, otherwise `unavailable`.

## Implemented endpoints

All paths are prefixed with `/api/v1`:

- `GET /health`
- `GET /catchments`
- `GET /catchments/{id}`
- `GET /catchments/{id}/observations?from=<ISO-8601>&to=<ISO-8601>`
- `GET /catchments/{id}/warnings`
- `POST /catchments/{id}/assessments`
- `GET /sources/status`

Schemas and status values are defined in `app/schemas/api.py`; OpenAPI is generated by FastAPI. Unknown catchments return 404. Invalid timestamps or a `from` later than `to` return 422.

## Frontend integration contract

All response fields are typed in the OpenAPI document. The essential payload shapes are:

- Catchments: `{items: Catchment[], count: number, is_demo: boolean}`. Catchment fields: `id`, `name`, nullable `region`, `geometry`, `geometry_source`, `validation_status`, `is_demo`.
- Observations: `{catchment_id, items: Observation[], source_state, is_demo}`. Each observation carries `source_id`, `provider`, `variable`, nullable `value` and `unit`, `observed_at`/`issued_at`, `fetched_at`, validity times, geographic coverage, `freshness`, `source_state`, `quality_flags`, and `is_demo`.
- Warnings: `{catchment_id, items: WarningItem[], source_state, is_demo, message}`. Empty items plus the message “No warning provider is configured; this is not confirmation that no official warning exists.” must not be shown as an authoritative all-clear.
- Assessment POST body: `{}` or `{ "requested_at": "<ISO-8601 timestamp>" }`. Response includes `assessment_id`, `catchment_id`, `status`, nullable `score`, `score_semantics`, `model_version`, `issued_at`, `is_demo`, `data_coverage` (`required_inputs`, `available_inputs`, `missing`, `stale`), `reason_codes`, `sources`, and `warnings`.
- Source status: `{items: SourceStatus[], is_demo}`. Each source lists capability, provider, state, source/fetch time where known, units, geographic coverage, freshness, quality flags, and a human-readable message.

Assessment statuses use `low`, `moderate`, `high`, `very_high`, `insufficient_data`, `degraded`, or `unavailable`. The current baseline never calculates a score: absent required inputs return `insufficient_data`, null score, and `INSUFFICIENT_REQUIRED_INPUTS`. A score is not a probability unless separately calibrated.

## Current implementation and limitations

Provider connector abstractions have timeout/error handling, but the registry is empty. Rainfall, forecast, official warning, terrain and hydrology are reported unavailable; source metadata is not fabricated. The risk service checks required-input freshness and returns insufficient/degraded states, but there is no threshold model. Unit conversion is not implemented. Supabase storage, auth, migrations, history and assessment persistence are not wired; no migration was changed. Persistence and external integrations need separate implementation and verification before being described as functional.
